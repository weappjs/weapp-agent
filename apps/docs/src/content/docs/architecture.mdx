## 模块边界

本实验分支将 CLI 切换到 Pi agent-core + Pi AI 0.85.1；自研基线固定在 `7e14726`。原引擎与 AI SDK 适配保留用于离线契约对比，不提供 CLI 后端切换开关。完整结果见仓库的 `reports/pi-comparison.md`。

Pi 管理顺序工具循环；本项目保留权限、工具实现、JSONL 审计、上下文预算及修改后验证。工具内部检查仍是执行权限的最终边界，Pi 钩子在审批拒绝后阻止后续调用。原始 Pi assistant 元数据与规范消息一起脱敏持久化，以保留多轮对话所需签名；旧会话没有这些元数据时使用规范消息转换。

CLI 负责终端交互和命令参数；core 负责会话、工具循环、权限和文件操作；providers 负责模型协议转换；mini-program 负责工程识别、验证与 MCP；docs 使用 Nimbus 独立构建。

`ModelAdapter` 暴露异步事件流；`Tool` 声明 schema 与执行方法；`ProjectAdapter` 提供工程事实、指令和工具；`SessionEvent` 是带版本的持久化事件。

模型适配器只生成文本与工具请求，不执行工具。Pi 顺序调度经过 core 包装的工具，写入日志后再执行，从边界上避免网络请求重试重复执行工具。

## 首版边界

采用 API Key，不实现订阅账号 OAuth。提供本地工具权限，不提供 OS 级沙箱。框架适配先聚焦微信与 weapp-vite；多平台、Web 工作台、并行子 agent 留待后续独立设计。

文件编辑使用读取哈希校验与原子替换，降低覆盖并发改动的风险；仍建议避免两个进程同时编辑同一文件。
